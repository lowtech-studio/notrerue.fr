## deploy/harden.sh

Les problèmes bloquants des revues précédentes sont bien corrigés (drop-in renommé en `00-`, vérification des valeurs effectives via `sshd -T`, échec de reload tracé, `mktemp` pour le sudoers, `touch` avant `augenrules`, `SSH_ALLOW_USERS` documenté en en-tête). Reste quelques points mineurs :

- `systemctl enable --now systemd-timesyncd … || true` suivi de `SUMMARY_APPLIED+=("… vérifiée active")` : si le enable échoue, le résumé affirme quand même le succès (déjà signalé dans la revue précédente, toujours présent). Même motif pour AppArmor (« service vérifié actif » après `|| true`). À tracer en SKIPPED/MANUAL comme c'est désormais fait pour le reload SSH.
- `sshd -t 2>/tmp/sshd-config-test.log` : fichier à nom prévisible dans `/tmp`, exactement le motif corrigé avec `mktemp` pour le sudoers quelques sections plus bas — incohérent. Risque faible (script root sur VPS mono-admin) mais `mktemp` coûte une ligne.
- `touch -a /var/log/sudo.log` crée le fichier en 0644 (umask root par défaut) s'il n'existe pas, alors que sudo le créerait en 0600 : le journal des commandes sudo (arguments potentiellement sensibles) devient lisible par tout compte local, y compris le compte de service `notrerue`. Un `chmod 600` après le `touch` alignerait sur le défaut de sudo.
- auditd : les `sed -i 's|^max_log_file…|…|' || true` ne font rien silencieusement si les clés sont absentes ou commentées dans `auditd.conf` (sed ne renvoie pas d'erreur sans correspondance), alors que le résumé annonce « logs bornés à 60 Mo ». Le motif grep-ou-append utilisé pour `pwquality.conf`/`login.defs` serait plus sûr.
- `sysctl --system` tourne sous `set -e` : une seule clé non supportée par le noyau courant (ex. `kernel.yama.*` hors Ubuntu) aborte le script en plein milieu, laissant les sections suivantes non appliquées sans résumé. Cible Ubuntu rendant ça improbable, mais un `|| true` ou une application clé par clé rendrait le script plus robuste.
- Section `HARDEN_TMP_NOEXEC` : `mount -o remount,nodev,nosuid,noexec /tmp` sur un bind mount frais peut ne pas appliquer les options sans le flag `bind` explicite selon les versions noyau/util-linux, et le `|| true` masque l'échec alors que le résumé dit « appliqué » (l'entrée fstab garantit l'état correct au reboot, donc mineur).
