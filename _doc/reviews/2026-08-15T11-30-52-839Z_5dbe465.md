### deploy/monitor.sh
- **Référence doc cassée** : le commentaire renvoie vers `deploy/README.md « Supervision externe »`, mais aucune section de ce nom n'existe dans le README (la partie concernée est un paragraphe en gras sous « 4. Logs et supervision »). Même problème dans le message final de `provision.sh`. À aligner (renommer la section ou corriger les renvois).
- **`curl` sans timeout** : si l'API Brevo pend, le service oneshot reste bloqué jusqu'au `TimeoutStartSec` de systemd. Un `--max-time 20` éviterait ça.
- **Échec d'envoi = abandon du passage** : si `send_alert` échoue (Brevo down, clé invalide), `set -e` interrompt le script et les métriques suivantes ne sont pas vérifiées ce tour-ci. Le fichier d'état n'étant posé qu'après succès, la tentative sera rejouée au tick suivant — comportement défendable, mais à garder en tête (une clé Brevo cassée = supervision totalement muette, y compris pour les autres métriques).
- **Mineur** : `BREVO_API_KEY` apparaît dans la ligne de commande de `curl`, donc visible via `ps`/`/proc` pendant l'appel. Risque faible sur un VPS dédié, mais un `--config` ou un header via fichier l'éviterait.
- **Mineur** : `source "$ENV_FILE"` soumet le fichier env aux règles de quoting bash — une valeur avec espaces non quotée (ex. `EMAIL_FROM=Nom <a@b>`) casserait le script. À documenter ou à parser autrement.
