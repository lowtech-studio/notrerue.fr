## Revue

### mobile/app/(app)/fil.tsx
- `handlePublished` : le commentaire annonce « première page, sans filtre actif ni recherche », mais le code ajoute **toujours** la demande en tête. Avec un filtre « Je propose » actif (ou une recherche), une demande « cherche » fraîchement publiée apparaîtra dans une liste qui ne la concerne pas. Soit conditionner le prepend (`!activeType && !search && page === 1`), soit corriger le commentaire.
- Conséquence du prepend : la pagination décale d'un cran, et « charger plus » (page + 1) peut ramener en doublon le dernier item de la page 1 (clés dupliquées dans la `FlatList`). Mineur, mais visible.

### mobile/components/fil/PostComposer.tsx
- L'alerte « Photo non jointe » suggère de « réessayer de l'ajouter **en modifiant la demande** » — or la modification (PATCH, comme sur le web) ne permet que le texte, jamais la photo. Le message promet un chemin de récupération impossible : reformuler (supprimer/republier) ou rester vague.
- Reset partiel après publication : `content`, `image`, `duration` sont réinitialisés mais pas `type`. Si c'est assumé (confort), OK ; sinon incohérent.

### mobile/components/fil/PostCard.tsx
- `handleTap` et `handleDelete` : échec totalement silencieux (`if (!result.ok) return;`). Le tap ne se produit juste pas, la suppression reste bloquée sur « Confirmer ? » sans explication. Afficher au moins un message d'erreur, comme pour l'édition et les commentaires.
- `maxLength={240}` en dur alors que `MAX_POST_CONTENT_LENGTH` existe dans `PostComposer.tsx` — extraire la constante partagée (avec `MAX_COMMENT_CONTENT_LENGTH`) plutôt que dupliquer le magic number.

### mobile/lib/api.ts
- `photoUrl` est exporté mais jamais utilisé (`PostImage` appelle `authFetch("/photos/...")` directement) — dead code à supprimer ou à faire utiliser par `PostImage`.
- Le commentaire de `authFetch` cite « ex. lib/photos », module inexistant — référence obsolète (le vrai consommateur est `components/fil/PostImage.tsx`).
- L'interface `Comment` entre en collision avec le type DOM global `Comment` et diverge du nommage web (`PostComment`, cf. `db/comments.ts`) — renommer en `PostComment` pour la cohérence inter-projets revendiquée partout ailleurs.

### web/routes/api/v1/posts/index.ts
- POST : le redimensionnement d'image (opération la plus coûteuse du endpoint) est effectué **avant** la validation type/durée/contenu et avant `postCooldown.record`. Un compte vérifié peut donc envoyer en rafale des requêtes invalides avec des images de 5 Mo — chacune déclenche un resize, aucune n'alimente le cooldown. Traiter l'image après validation du reste, ou enregistrer le cooldown plus tôt.
